# 1주차 — 정산 도메인을 축으로 한 MSA 서비스 경계 설계

> 주문 도메인 분석에서 출발하여, **정산(Settlement)을 핵심 도메인(Core Domain)으로 놓고** 서비스 경계를 설계합니다.

| 항목 | 내용                                                                          |
|---|-----------------------------------------------------------------------------|
| 과제 | 주문 도메인 기준 MSA 서비스 경계 설계                                                     |
| 설계 축 | **정산(Settlement) 중심**                                                       |
| 기준 코드 | `com.example.demo` (Spring Boot 4.1.1 / Java 21 / PostgreSQL / Spring Batch) |
| 서비스 구성 | **5개** — Settlement · Order · Payment · Product · Member                    |
| 이번 범위 | **1. 수집 -> 2. 계산 -> 3. 집계·마감 -> 4. 매출 대사** (지급은 다음 단계로 이연)                  |
| 문서 상태 | **재설계 반영 완료** - ADR 26건 확정 · 남은 확인 3건                                       |

### ① PG 수수료 절사 규칙 — 가장 먼저 확인할 것

[ADR-025](adr/0025-대사-범위-편입.md)에서 대사 허용 오차를 **0원**으로 잡았습니다. 토스 수수료는 `supplyAmount`(공급가액) + `vat`(부가세) 구조이고 **부가세에 원 단위 절사**가 들어갑니다. 요율만 맞추고 절사 규칙이 다르면 **정상 거래가 전건 불일치**로 잡힙니다.

### Q6. 배치 메타를 같은 DB의 별도 스키마로?

| 선택지 | 관심사 분리 | 트랜잭션 원자성 | 설정 복잡도 |
|---|:---:|:---:|:---:|
| **별도 DB** (현재 결정) | ✓ | ✗ — R-04 발생 | DataSource 2개 |
| **같은 DB · 별도 스키마** | ✓ | **✓ 유지** | DataSource 1개 |

```yaml
spring:
  batch:
    jdbc:
      table-prefix: batch.BATCH_     # batch 스키마에 메타 테이블 생성
```

이 절충을 택하면 **R-04가 통째로 사라집니다.** 전사 공용 배치 DB로 승격할 계획이 생기면 그때 별도 DB로 빼도 늦지 않습니다.

### Q7. 조정 전표의 역할 검증 위치

| 선택지 | 장점 | 단점 |
|---|---|---|
| **Gateway** | 핵심 도메인이 인증을 모름. 정책을 한곳에서 관리 | Gateway 우회 내부 호출은 무방비 |
| **Settlement** | 호출 경로와 무관하게 항상 검증 | 핵심 도메인이 역할·인증 개념을 알게 됨 |
| **양쪽 모두** | 1차 + 2차 — 실무의 일반적 형태 | 역할 정의가 두 곳에 존재 |
