# ADR-021. 정산 배치는 k8s CronJob으로 실행하고 ShedLock으로 중복을 막는다

> 🟢 **승인 (Accepted)** — F3

---

- **상태**: 승인 · **관련**: [ADR-017](0017-배치-grpc-pull-수집.md), [ADR-010](0010-배치-메타-db-분리.md), [ADR-025](0025-대사-범위-편입.md)
- **맥락**: 현행 코드에는 **스케줄러가 없다.** `POST /api/batch/jobs/settlement`로 수동 실행만 가능하므로 신규 도입이다. `@Scheduled`(A) / k8s CronJob(B) / 외부 트리거(C)를 검토
- **결정**: **안 B — k8s CronJob.** 다중 인스턴스를 전제하고 **ShedLock으로 중복 실행을 차단**한다

| 잡 | 시각 | 대상 |
|---|---|---|
| 정산 마감 배치 | **매일 03:00** | 전일(D-1) 거래 |
| 대사 배치 | **매일 06:00** | **D-3** 일자 ([ADR-025](0025-대사-범위-편입.md)) |

- **근거**
  - 스케줄이 **애플리케이션 밖에** 있어 배포 없이 조정할 수 있다
  - 실행 이력·실패 알림이 클러스터 레벨에서 관측된다
  - `@Scheduled`는 인스턴스 수만큼 동시에 돈다 — 정산에서 **이중 실행은 이중 계상**이다
- **ShedLock이 필수인 이유**
  - 정산 배치의 이중 실행은 곧 **원장 이중 적재 → 판매자 과다 지급**으로 이어진다
  - 멱등 키(`source_event_id` UNIQUE, [ADR-019](0019-정산-aggregate-2개-분리.md))가 1차 방어선이지만, 마감 상태 전이·집계 갱신까지 멱등을 보장하려면 잠금이 더 싸다
  - CronJob도 노드 재스케줄·재시도 상황에서 중복 기동이 가능하므로, 오케스트레이터만 믿지 않는다
- **포기한 것**
  - k8s 매니페스트가 배포 산출물에 추가된다 (로컬 개발은 수동 실행 API를 유지)
  - ShedLock용 잠금 테이블이 하나 더 필요하다
- **재검토 조건**: 잡이 여러 개로 늘어 의존 순서(마감 → 대사)를 코드 밖에서 표현해야 할 때 → 워크플로 엔진(Airflow 등) 검토
