# ADR-026. 설계 문서를 전략 / 전술 / ADR로 분리한다

> 🟢 **승인 (Accepted)** — F8 C안

---

- **상태**: 승인 · **관련**: 전 ADR
- **맥락**: 피드백 7번 — *"전략적 / 전술적 설계 문서를 따로 만들 것."* 기존 `README.md`가 **1,395줄** 한 파일이었고, 재설계로 무효화된 내용과 유효한 내용이 섞여 **어느 문서를 봐야 하는지 알 수 없는 상태**였다
- **결정**: **ADR을 파일별로 분리하는 C안**

```
docs/1week/
├── README.md               # 개요 · 결정 요약 · 인덱스
├── strategic-design.md     # 전략적 설계
├── tactical-design.md      # 전술적 설계
├── as-is-and-migration.md  # AS-IS 분석 · 전환 계획 · 자가 점검
├── REDESIGN-DECISIONS.md   # 재설계 결정 시트 (F1~F9) — 이력 보존
└── adr/
    ├── 0001-정산-지급-2분할.md
    └── ...  (0026까지)
```

| 문서 | 담는 것 |
|---|---|
| **전략적 설계** | 서브도메인 분류 · Bounded Context · **Context Map + 관계 패턴**(ACL, OHS, Customer-Supplier) · 서비스 경계와 책임 · 의존 관계 |
| **전술적 설계** | **Aggregate 설계** · Entity / VO · Repository · 도메인 서비스 · 원장 스키마 · **불변식과 보장 수단** · 배치·대사 설계 |
| **AS-IS · 전환** | 현행 분석 · Phase 계획 · 체크포인트 자가 점검 |
| **ADR** | 결정 1건 = 파일 1개. 폐기·개정 상태를 파일 머리에 표시 |

- **근거**
  - **ADR은 개별 수명을 갖는다.** 이번 재설계에서 3건이 폐기되고 2건이 개정됐다. 한 파일에 몰아두면 *"어느 결정이 아직 살아 있는가"*가 보이지 않는다
  - 파일별로 두면 **폐기 표시가 파일 머리에 남아** 이력이 보존된다. 지운 결정도 왜 지웠는지 읽을 수 있다
  - 전략/전술 분리는 피드백 7번의 직접 요구다
  - AS-IS·전환 계획은 설계가 아니라 **작업 계획**이라 별도 파일로 뺐다
- **포기한 것**
  - 파일이 30개가 넘는다. 전체를 훑기 어려워지므로 **README 인덱스가 필수**다
  - ADR 간 상호 참조를 상대 경로로 관리해야 한다
- **기존 README 처리**: 개요·인덱스로 축소하고 내용은 세 문서로 이전했다. `REDESIGN-DECISIONS.md`는 **재설계 과정의 기록으로 남긴다** — 무엇이 왜 뒤집혔는지는 ADR만으로는 복원되지 않는다
- **재검토 조건**: 2주차 이후 문서가 더 늘어날 때
