# ADR-018. 수수료는 배치 시점에 계산하되, 거래 발생일의 정책을 적용한다

> 🟢 **승인 (Accepted)** — F2-b · [ADR-003](0003-거래시점-수수료-계산.md)을 대체

---

- **상태**: 승인 · **관련**: [ADR-017](0017-배치-grpc-pull-수집.md), [ADR-004](0004-전표식-원장.md), [ADR-025](0025-대사-범위-편입.md)
- **맥락**: 수집이 배치가 되면서([ADR-017](0017-배치-grpc-pull-수집.md)) 계산 시점은 자동으로 **배치 실행 시점**이 됐다. 남은 선택은 *어느 날짜의 수수료 정책을 적용하는가*다. 거래 발생일 기준 / 배치 실행일 기준
- **결정**: **거래 발생일 기준.** 1/15 거래는 배치가 1/16에 돌더라도 **1/15 시점의 정책**을 적용한다
- **근거**
  - **정책 변경이 소급되지 않는다.** 요율이 바뀌었다고 지난 거래의 정산 금액이 달라지면 판매자와 분쟁이 난다
  - 판매자 계약은 통상 *"거래일 기준 요율"*로 쓰인다 — 도메인 언어와 일치
  - 불변식 **I7**(정산 결과는 상류 데이터가 바뀌어도 불변)과 결이 같다
  - 재처리 안전성 — 같은 날짜를 며칠 뒤에 재실행해도 **같은 금액이 나온다.** 배치 실행일 기준이면 재실행 시점에 따라 금액이 달라져 멱등성이 깨진다
- **포기한 것**
  - `fee_policy`를 시점 조회가 가능한 형태로 둬야 한다 (`effective_from` / `effective_to`)
  - 구현이 "현재 정책 하나 읽기"보다 복잡하다
- **불변식 I5 보장**: 적용한 `feePolicyId`를 **전표에 기록**한다. 계산 근거를 언제든 재현할 수 있어야 하며, 이는 [ADR-025](0025-대사-범위-편입.md)의 `AMOUNT_MISMATCH` 원인 추적에도 직접 쓰인다
- **⚠️ 절사 규칙 제약**: [ADR-025](0025-대사-범위-편입.md)에서 대사 허용 오차를 **0원**으로 잡았으므로, 수수료 계산의 **절사·반올림 규칙이 PG와 동일해야 한다.** 요율만 맞추고 절사가 다르면 정상 거래가 전건 불일치로 잡힌다
- **재검토 조건**: 판매자별 소급 정산 요구가 실제로 들어올 때
